# 两周探索与搭建计划

## 目标与范围

两周内交付一个中文语音对话原型，加上可重复的 ASR、TTS、降噪对比实验。第一版按“录一段、答一段”工作；流式、语音打断、回声消除和视觉输入作为后续扩展。

这里的计划按 14 个日历日安排；若按工作日执行，可压缩为 10 天。每天记录环境、做了什么、遇到的问题、结果文件路径和下一步，便于最终写报告。

## 每日安排

| 时间 | 主要工作 | 当天应看到的结果 |
| --- | --- | --- |
| 第 1 天 | 理解任务、安装环境、确定中文和短语音范围 | 环境记录、结构图、依赖安装完成 |
| 第 2 天 | 下载 Whisper 和中文 VITS，分别测试 | 一段 WAV 的转写、一段中文合成音频 |
| 第 3 天 | 安装 Ollama，接通 ASR → LLM → TTS | 能完成一轮真实语音对话 |
| 第 4 天 | 测网页录音、多轮上下文、失败提示 | 3–5 轮对话演示，错误可定位 |
| 第 5 天 | 安装 SenseVoice，用固定录音对比 ASR | 两种 ASR 的初步 CER / RTF |
| 第 6 天 | 下载 Kokoro，测试两种 TTS | 同一批文本的两套 WAV 和耗时 |
| 第 7 天 | 整理第一周成果、修复主要部署问题 | 可复现启动步骤、阶段演示 |
| 第 8–9 天 | 整理 30–50 条人工校对录音，采集噪声 | 干净数据清单、至少 3 类噪声 |
| 第 10 天 | 生成 20 / 10 / 0dB 混音，跑降噪实验 | 无降噪、高通、谱门控三组结果 |
| 第 11 天 | 分析失败样例、必要时调一组参数 | 改善与退化案例、解释原因 |
| 第 12 天 | 真实噪声现场测试、组织小样本听评 | 现场 CER、TTS 主观评分 |
| 第 13 天 | 汇总图表、模型选型、限制与下一步 | 报告初稿 |
| 第 14 天 | 从启动步骤复现，录制演示 | 代码、报告、结果 CSV、2–3 分钟演示 |

时间不足时，优先保证一条真实语音链路、两种 ASR 和两种 TTS 的小规模对比，再完成一种噪声与一种降噪算法的实验。不要为了增加候选模型数量而失去可复现的结果。

## 应交付的材料

1. **代码与启动说明**：环境版本、模型来源与版本、路径配置、启动命令。
2. **架构说明**：数据流、各模块职责、如何更换模型、当前限制。
3. **模型比较表**：ASR 的 CER / RTF；TTS 的 RTF、听评、读错案例；部署难度和资源占用。
4. **抗噪声实验**：噪声类别、SNR 定义、处理方式、各条件 CER、真实现场结果。
5. **演示**：干净环境对话、嘈杂环境对话、文字与语音回答、耗时显示。

## 验收方法

- 按 README 可启动，在下载好权重后完成至少 5 轮真实语音问答。
- 切换两种 ASR 和两种 TTS 能分别得到真实转写或 WAV，不使用替代模型输出冒充推理结果。
- 噪声对比使用相同语音、参考文本和设备设置，有明确的“关闭降噪”基线。
- 报告对失败结果同样保留记录；降噪没改善也是有效结论，需要解释限制。
- 能说明冷启动、预热后推理和用户感知总等待时间的区别。
- 空录音、无法连接 LLM、缺少 TTS 权重时，页面给出可理解的错误。

## 实验纪律

- 数据按调参集和最终测试集划分，先固定参数再跑最终测试；不要看测试答案反复调参数。
- 同一比较中固定麦克风、语言、音频长度范围、机器、设备和线程设置。
- 明确比较的是 ASR 模型本身还是包含 VAD / 降噪的系统。当前 Whisper 配置含 VAD，SenseVoice 未额外接入 VAD，报告要写明。
- 使用同一参考文本规范，记录简繁体、数字和英文词的计分规则。
- 小数据集报告逐条结果与汇总，重要结果重复运行 3 次，耗时可报告中位数。
- 降噪强度不能只用主观听感选择，最终以测试集 CER 和延迟共同判断。
- TTS 主观听评随机化样音顺序，记录人数和评价方法；少量同学的评分不代表总体人群。
- 手工记录 `nvidia-smi` 的显存和任务管理器内存；脚本目前只自动统计耗时。
